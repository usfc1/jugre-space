# JUGRE: PhysX / WASM

## Запуск

Откройте `assembly_hangar/index.html` в Edge/Chrome с WebGL. Сервер, CDN и загрузка WASM из сети не нужны: JavaScript, модели и бинарник PhysX встроены в HTML. Выберите «Стартовая площадка», Apollo 11 / Artemis II / «Снабжение МКС», затем «Начать полёт».

Для пересборки из `assembly_hangar/source`:

```powershell
npm ci
npm run build
npm test
npm run test:physx
npm run verify:physx
npm run verify:launches
```

Браузерные команды требуют установленного Microsoft Edge; `verify:physx` также принимает `PLAYWRIGHT_CHANNEL`. Они открывают **обычный собранный `index.html` через `file://`**, загружают миссии штатным интерфейсом и используют существующее сохранение для контрольных состояний. Это проверки живых участков миссий, а не утверждение о ручном прохождении всех миссий от отсчёта до финала.

В «Диагностике физики» доступны настоящие состояние PhysX, число тел/контактов/соединений, положение свободных предметов, ошибки положения модели и массы. «Толкнуть предмет в кабине» работает после выбора камеры «Борт». «Испытание ударом» запускает физический обломок в корпус. Для терминального участка стыковки предусмотрены «Быстрое сближение» и «Сбой ориентации»: они изменяют скорости тел, а результат определяют контакты и датчики портов.

## Бэкенд и платформы

Закреплён `physx-js-webidl@2.9.1`, реальная версия SDK `5.12.0` (`PHYSICS_VERSION = 84672512`). Используется CPU / WebAssembly; CUDA не требуется. Основа: [репозиторий сборки](https://github.com/fabmax/physx-js-webidl), [NVIDIA PhysX](https://github.com/NVIDIA-Omniverse/PhysX).

`physx-runtime.mjs` передаёт встроенный бинарник через `wasmBinary`. `locateFile` задан явно: исходная Emscripten-сборка иначе пытается разрешать `import.meta.url`, который не сохраняется при упаковке в IIFE. Проверена совместимость с текущим esbuild. Ошибка инициализации останавливает начало полёта и показывается в интерфейсе; подмены PhysX анимационным бэкендом нет.

Реальный запуск проверен в Edge и Electron 45.2.3 / Chromium 156.0.8078.80, с `sandbox`, `contextIsolation` и отключённым `nodeIntegration`. Отчёт Electron: `diagnostics/physx/electron-verification.json`. Повторная проверка: из `desktop` запустить `electron verify-physx.cjs`, используя установленный Electron либо `desktop/.cache/physx-runtime/electron.exe` после проверки SHA-256 архива. Готовый старый portable EXE не пересобирался; `desktop` → `npm run build:win` упакует обновлённый автономный HTML без дополнительных WASM-файлов.

MIT и уведомления NVIDIA сохранены в `source/physx-NOTICE.txt` и встроены в HTML. В уведомлении upstream осталось историческое упоминание 5.6.1; фактически загруженная версия проверяется по бинарнику и равна 5.12.0.

## Архитектура и владение положением

| Участок | Владелец основного движения | Роль PhysX |
| --- | --- | --- |
| Старт и околоземная орбита | `LaunchDynamics`, SI, вращающаяся ECEF | Локальное отклонение корпуса после контакта, вращение, независимые ступени |
| Перелёт к Луне, лунная орбита/облёт и возвращение Apollo/Artemis | `lunar-trajectory.mjs` / `orbital-propagator.mjs`, км / км/с / с | Локальная динамика и контакты; при спокойном свободном полёте возможен аналитический пропуск пустых шагов для ×300/×500 |
| Межпланетный перелёт и спуск | `FlightState` / `mission-paths.mjs` | Динамика рядом с кораблём; крупномасштабная учебная траектория не интегрируется повторно |
| Отделённая ступень / обтекатель / Eagle | Независимый actor PhysX | Положение, ориентация, контакты и импульсы; модель больше не следует за родителем |
| Дальнее сближение | Контроллер миссии | Измерение поз и скоростей для передачи управления |
| Сближение в пределах 20 м | PhysX + локальный автопилот | Контакты, проверка портов, fixed joint, физический отказ захвата |
| Разворот CSM и извлечение Eagle | Направляемый манёвр существующего сценария | Захват подтверждается положением, углом и измеренной относительной скоростью; связка затем представлена составным actor |
| Интерьер | Отдельная сцена PhysX в координатах кабины | Статичные относительно корпуса кресла/панели/стены и два свободных тела |

Основной цикл — `viewer.mjs` → `flight-view.mjs`. `FlightState.update` передаёт длительность каждого подшага в `simulationHardware`. PhysX использует фиксированные **1/120 с** и `fetchResults`; рендер использует интерполяцию предыдущей/текущей позы. Warp передаёт симулируемое время, пауза не продвигает физику. Долгий кадр не выбрасывает оставшееся время.

Орбитальные координаты миссии хранятся в километрах. Локальные сцены, GLB, коллайдеры и скорости PhysX используют метры, килограммы, секунды и радианы. Продольная ось корпуса — `+Y`, **ось mount/порта в GLB — `+Z`**. Внешняя локальная сцена сохраняет ориентацию осей ECEF и движется вместе с опорной траекторией; при рендере применяется обратное вращение `flightFrame`. Большие межпланетные координаты не поступают в float-координаты PhysX.

Корпус получает движение опорной траектории один раз. Динамический actor хранит только локальное отклонение. Обломок получает `V_корабля + ω × r + V_разведения`; в локальной сцене хранится относительная скорость. Во время старта к отделённым телам прикладывается `g_кажущаяся − a_опорной_траектории`, включая учтённую игрой вращающуюся Землю. Общая тяга ракеты к ним повторно не прикладывается. Жизнь обломков короткая: это локальная модель, а не отдельный высокоточный орбитальный propagator.

При передаче управления сохраняются поза и скорости. Reparenting использует `attach`, поэтому отделение не меняет мировую позу модели. Ступень вместе с межступенчатым отсеком получает один actor. Начальные пересечения исключаются фильтром семейства до расхождения консервативных габаритов; позиционного выталкивания при отделении нет. CCD включён на сцене, телах и парах контактов.

Центр масс локального actor задан в опорной точке модели; тензор инерции вычисляет PhysX по составным коллайдерам. Это приближение: перемещение топлива и точный распределённый центр масс не моделируются. Масса ракеты изменяется вслед за `LaunchDynamics`; после извлечения аппарата используются массы оставшихся модулей, вместо массы всей стартовой сборки.

## Интерьер, повреждения и очистка

Коллайдеры кресел, панелей, пола, стен и потолка строятся из фактических размеров кабины; дополнительная передняя стенка закрывает окна. Размеры профилей Columbia / Orion / Eagle / «Контур» переводятся в физические метры. Эти статические тела неподвижны в системе кабины. Интерактивных полётных люков в текущем сценарии нет; декоративные люки не получают фиктивных шарниров.

Свободные предметы получают противоположное собственному ускорению корпуса ускорение, члены Эйлера, центробежный и Кориолиса. В свободном падении собственное ускорение равно нулю. Ускорение старта берётся из силового двигателя; для учебных посадок/коррекций, где траектория кинематическая, используются явно заданные игровые параметры. Удар передаёт реальное изменение скорости корпуса ровно один раз. Оно не дифференцируется повторно в постоянную силу.

Контактная callback PhysX предоставляет скорость в точке, импульс и зону shape. `FlightSystems.impact` считает энергию с приведённой массой и применяет настраиваемый удельный порог к конкретному модулю. Слабое касание безопасно. Пробоина обитаемого модуля вызывает утечку и снижение давления, предупреждение ниже 55 кПа и отказ ниже 20 кПа. Это игровой баланс, не расчёт реальной герметичности. Повреждение ступени может отказать её двигателю. События `moduleDamage`, `dockingContact`, `dockingRejected` доходят до существующего `mission-control` и HUD.

Контакты отслеживаются по парам shapes внутри пары actors: длительное касание не повторяет начальный удар. После полного расхождения новая встреча может нанести новый урон с cooldown. Активных обломков не больше 32. При смене/перезапуске миссии освобождаются actors, shapes, joints, callback и интерьер; история контактов и повреждения очищаются.

Сохранение восстанавливает движение корпуса, цель и соединение стыковки, Eagle и свободные предметы. Как и прежние checkpoint-сохранения игры, краткоживущие обломки при загрузке очищаются и не воссоздаются возле аппарата.

## Проверки и подтверждённые исправления

Исходные 53 модульных теста проходили до изменений. В исходном дереве уже был общий `LaunchDynamics`; заявленный отдельный дефект стартовой траектории не удалось подтвердить на Apollo 11 и Artemis II. Поэтому силовой расчёт не заменялся произвольной правкой. Проверены положение/курс модели на T+12, T+60 и перед отделением, а также живой переход через 650 м со стартовой площадки в floating origin. Измеренная ошибка положения модели меньше 1 мм; изменение относительного положения камеры через переход — около 0,3 м, без скачка системы координат.

Подтверждена и исправлена другая общая ошибка: выражение `moving.position.copy(destinationPort).sub(sourcePort())` **сначала меняло moving.position, затем измеряло sourcePort в уже перемещённой модели**. Новый `alignDockingPorts` измеряет обе точки до изменения transform. Исправление используется при сближении МКС; прежнее анимационное отделение Eagle заменено независимым телом. Регрессионный тест включает перемещённого и повёрнутого родителя.

Общий AABB станции и открытой крышки Dragon создавал ложные контакты в пустом пространстве. МКС получила отдельные ориентированные коллайдеры модулей Harmony/Kibo/адаптеров и остальных корпусов; габарит корпуса Dragon ограничен плоскостью стыковочного узла, кольцо имеет собственные shapes.

## Непроверенное и границы

- Полные визуальные прохождения Mars 2020, MSL, Voyager 2 и DART после интеграции не выполнены: в этом прогоне проверены их силовые траектории и общая сборка, но браузерные сценарии сосредоточены на трёх миссиях выше.
- Художественная финальная сцена DART сохраняет прежний raycast-контакт и эффект выброса породы; удар на 6,1 км/с не объявляется новым PhysX-тестом.
- Safari, Firefox, мобильные устройства и другие ОС не проверялись: в доступной среде Windows проверены Edge и Electron. Требуются WebAssembly и WebGL.
- Число кадров тяжёлой сцены с 32 обломками, полным ландшафтом и интерьером не сертифицировано. Приведённый замер относится к двум физическим сценам без стоимости WebGL, а не к FPS всей игры.
- Готовые ZIP и portable EXE не пересобирались: проверен обновлённый HTML в Electron; старые файлы `release` продолжают содержать прежнюю версию игры до `build:win`.
- Орбитальные перелёты, газодинамика пробоины, разрушение сетки и распределение топлива не заменены на инженерные модели. Пороги, массы отдельных модулей и параметры терминального автопилота остаются учебными приближениями.
